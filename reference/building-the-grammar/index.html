    4. Building the grammar¶

    Kurt's grammar is not fixed — the fixity, precedence, and arity of every operator (including implies/and/space itself) is declared from Kurt source, using a small set of keywords, and looked up dynamically by the parser (a Pratt/TDOP parser). This is what "extensible from Kurt source" means throughout CLAUDE.md.

    4.1 infix, prefix, postfix¶

    infix OP lbp rbp     ; e.g. infix "+" 20 20
prefix OP rbp        ; e.g. prefix "-" 100
postfix OP lbp       ; e.g. postfix "!" 100

    Each accepts a comma-separated list to declare several operators in one line (e.g. infix "+" 20 20, "-" 20 20). Binding powers control precedence and associativity: for infix, lbp > rbp makes the operator right- associative (as implies is: infix implies 13 12, so A implies B implies C parses as A implies (B implies C); and numbers.kurt's infix ^ 75 74, so 2 ^ 3 ^ 2 is 2 ^ 9); lbp == rbp (as with + above) makes it left-associative (a - b - c is (a - b) - c), and a flat operator (§4.5) collects all its arguments anyway. Declaring the same symbol both infix and prefix is allowed (useful for something like unary/binary -); declaring it as more than one of infix/prefix/postfix/a bracket otherwise is an error. Fixity alone does not classify a symbol as constant or variable.

    Called with no arguments (infix, prefix, postfix), each prints every currently-declared operator of that kind, across all open levels. The other property keywords (const, var, sort, prop, arity, brackets, bindop, chain, flat, sym, and alias) work the same way. Every listed entry's comment gives both its scope level and the source location that established that exact property, for example ; level 1, natural.kurt:20. A basename is shown normally; if two loaded files have the same basename, Kurt shows their paths to keep the locations unambiguous. Hard-coded core declarations have no source line and therefore show only their level.

    4.2 brackets¶

    brackets LEFT RIGHT     ; e.g. brackets "[" "]"

    Declares a new matching pair of bracket symbols. Only Kurt's own ( ) pair (declared exactly this way in minimal.kurt) is treated as pure, disappearing grouping — (A) really is just A. Any other bracket pair you declare yourself stays around as a genuine operator: [A] parses to a real term whose operator is an internal name combining [ and ] (rendered as [] if you parse/format sexpr it), not to A. Custom brackets are meant to carry their own meaning (e.g. ⟨a, b⟩ for a scalar product, brackets ⟨ ⟩; in the shell \langle, \rangle) via arity/prop/use axioms about the resulting operator, not as alternative parentheses. brackets takes exactly the two symbols — there is no separate binding-power argument. The two delimiter symbols become constants. A later prop LEFT ... or builtin LEFT ... declaration applies to the combined bracket expression, and listings print the source left delimiter rather than its internal combined name.

    4.3 arity¶

    arity SYMBOL N         ; e.g. arity f 2:         f a b
arity SYMBOL SHAPE     ; e.g. arity g (_, _):    g(a, b), one argument, a pair
                       ;      arity sum _ (_, _) _:  sum i (0, n) f

    Declares that SYMBOL is a plain (non-infix/prefix/postfix) function or predicate symbol taking exactly N arguments by space-application: f a b parses as one call (f a b). The shape says more, written as the symbol is used: _ for an argument, (_, _) for a tuple of two (also nested, ((_, _), _)); Kurt checks each use, so g(a) or g(a, b, c) with arity g (_, _) is an error ("g takes g (_, _)"), and a variable may stand for a tuple (g($p)). A symbol with no declared arity defaults to arity 0: it takes all the arguments that follow it, curried, and nothing checks them (§3.1). You cannot set an arity on a symbol that's already infix/prefix/postfix or a bracket (their arities — 2, 1, 1 — are implicit and fixed), and you cannot re-set an arity once declared.

    Round brackets group, so f(x) is f x, ((a)) is a, and f(x) = x * x reads as usual. Round brackets around a list are a tuple, a term of its own (since 0.9): (a, b) is a pair, (a, b, c) a triple, and (a, (b, c)) a pair whose second component is a pair -- so g(a, b) is g applied to one argument, the pair, never g a b (before 0.9: g a b for a g of arity 2). a, b, c without round brackets is a list: the elements in {a, b} or ⟨a, b⟩, or the formulas of use A, B; {(a, b)} is the set with one element, the pair. Binders (sum, ∀, ...) take their arguments as written, e.g. sum i (0, n) f with the pair (0, n).

    def defines a function of a tuple by its components, def f($x, $y) = ...: tuples are free, two are equal only if their components are, so this is conservative (doc/kurt-soundness.md §8.14).

    An operator alone in round brackets is the operator itself -- as the argument of an operator parameter, group(G, (∘), e, inv), group(R, (+), 0, (-)); (- x) is still - x. An operator is no object (§5.3): elsewhere, (+) or a bare f is a type error. An operator can also be a variable -- var ∘ and infix ∘ 70 70 -- then $a ∘ $b in a rule matches x + y as well as a ∘ b (by the rules of the operator it stands for, e.g. flat, sym). See group.kurt.

    A relation as a parameter works the same way: a variable with a statement as its result, var R and prop R 0, then R(x, y) -- or with infix R 20 20 also x R y, which matches x < y or x ∈ y -- e.g. def reflexive((R), $A) ⇔ ∀ x ∈ $A (x R x), and then reflexive((<=), A). ($R(x, y) is a term, not a formula: a $ variable stands for a term.) The symbols ~, ∼ (\sim), ≈ (\approx), ≺ (\prec), ≼ (\preceq) are free for relations of your own. Names may end in primes, a', f'', and a Greek letter may have digits, λ1.

    Empty brackets ((), {}, ...) are allowed and parse to nothing; the only place this is meaningful is directly after an arity-0 symbol, where f() then parses to exactly f — the same expression as writing f alone, matching ordinary mathematical usage of () for "no arguments." Directly after a symbol with a declared arity of 1 or more, f() is instead a clear, specific EvalError ("empty brackets () cannot supply an argument for f, which needs N argument(s)"), not a confusing parse — empty parens can never actually supply a real argument.

    4.4 bindop¶

    bindop SYMBOL     ; e.g. bindop forall

    Declares SYMBOL a variable-binding operator: its first argument is treated as a bound variable (or, with the sugar below, a condition, a statement whose free variable is the one being bound) for the rest of the expression. forall/exists are declared exactly this way, in logic.kurt (arity forall 2, exists 2, bindop forall, exists), together with their roles (builtin forall universal, ..., §8.1) and their axioms (forall-elim, exists-intro). For a plain space-applied binder, the symbol must already have an arity of at least 2 (the bound variable plus at least one more argument). An infix operator may instead be a binder, as set-builder | is: its left operand contains the condition and its right operand is the body. A binder cannot also be prefix, flat, sym, chained, calculator-bound, variable, or already used in a formula. bindop gives a fixed scope rule, so it makes the symbol a constant and reports const SYMBOL ; added constant when that role was not already explicit.

    The scope of the bound variable is the condition and the last argument, the body; arguments in between are outside of it, as in mathematics: in sum i (a, b) T the range (a, b), in lim v a T the point a. So in sum x (0, n) (sum x (0, x) x), the inner range (0, x) is the outer x.

    A schema variable in the body of a binder normally stands for something that does not depend on the bound variable — in (∀ $x ($x = $T)), $T is one fixed term. A statement variable %A may depend on it (that's what "forall-elim" is about), and so may a term variable $T of an axiom that occurs as the whole body of a binder over the same variable, and otherwise only inside binders over it or as the body of a sub for it, as in the sum axioms (sum $i ($a, $a) $T) = sub $i $a $T and (sum $i ($a, $b+1) $T) = (sub $i ($b+1) $T) + (sum $i ($a, $b) $T) (see analysis.kurt) — such a $T stands for any summand, which the axioms only ever use for the bound $i or with something substituted for it — or in the sum rule of derivatives, (diff $v $a $S) ∧ (diff $v $a $T) ⇒ (deriv $v $a ($S + $T)) = ... (derivative.kurt). Only an axiom (use, def, todo) is read like this, and not the variables of the ∀s it writes out: a proven fact holds for every term in place of its variables (a proof with let c is about terms c). This is decided by the form of the rule alone: there is no way to declare a dependence ($T[$i], as in Isabelle) or a distinct-variable condition ("$x doesn't occur in $T", as in Metamath) -- a decision (2026-10-06): the form shows where a dependence is meant, the kernel checks it, and no theory has needed more. Anywhere else, $T can't depend on the bound variable, and a rule that would need it can't be written.

    Conditions. The "bound variable" position may instead be a condition on it: ∀ $n ∈ Nat P($n), ∃ $d > 0 ..., lim $x > 0 0 (f $x). Unbracketed, it is a relation whose left-hand side is the variable; its right-hand side extends over infix operators (∀ $x ∈ A ∪ B ...) but stops at the first function application, which is where the body starts -- except for f(x) written without a space, which stays in the condition (∀ $x ∈ Perp(M) ...). In parentheses, any condition works, ∀ ($x > 0 ∧ $x < 1) (P $x). Which variable is bound: the first symbol of the condition, in the order it is written, that is new or a variable and not bound by an enclosing binder -- constants, predicates and operators are skipped. So ∀ x ∈ M ... binds a new x (also a plain name outside of a block), ∀ ($a ∈ $G) ... in a rule binds $a, ∀ ($x < $y) ... binds $x, ∀ c < x ... with a constant c binds x, ∀ (P $x) ... with a predicate P binds $x, and in ∀ (0 < e) (∀ (e < x) ...) the inner binder binds x (e is bound outside). Kurt decides this when it reads the line, before anything is reordered (a sym operator sorts its arguments), and stores the variable with the condition: the binder binds the same variable whenever the formula is used later, whatever is a constant then (when a block closes, its constants are free again -- this used to change the reading, and Kurt refused such a block). A printed formula reads back the same way. A condition without such a symbol is an error ("has no variable to bind").

    A condition is part of the formula: ∀ $x > 0 P($x) is not the same formula as ∀ $x ($x > 0 ⇒ P($x)), and the engine doesn't treat it as an implication. What a condition means is said by rules, like for any other operator — for ∀ and ∃ in logic.kurt:

    use (∀ (sub $x $v %C) %P) ∧ (sub $x $a %C)  ⇒  sub $v $a %P                     "forall-cond-elim"
use (sub $x $a %C) ∧ (sub $v $a %P)  ⇒  ∃ (sub $x $v %C) %P                     "exists-cond-intro"
use (∀ (sub $x $v %C) %P)  ⇔  ∀ $w ((sub $x $w %C) ⇒ (sub $v $w %P))           "forall-cond-def"
use (∃ (sub $x $v %C) %P)  ⇔  ∃ $w ((sub $x $w %C) ∧ (sub $v $w %P))           "exists-cond-def"

    In a rule (use/def), a binder sub $x $v %C stands for any condition: $v is the bound variable, and %C the condition with the hole $x for it — matching ∀ ($y > 0) ... gives %C = $x > 0, with every occurrence of the bound variable in the hole. So %C never mentions the bound variable itself, and %C may only be used with something substituted for $x, as sub $x ... %C (checked when the rule is stated). A binder with a condition never matches one without, so rules for both kinds are written separately (see lim in analysis.kurt).

    So from ∀ $x > 0 P($x) and 1 > 0 follows P 1 in one step ("forall-cond-elim"), while ∀ $x ($x > 0 ⇒ P($x)) takes a step of its own ("forall-cond-def") — e.g. to close ∀ $c ($c ∈ A ⇒ $c ∈ B) (the definition of A ⊂ B) after a let x ∈ A block, which gives ∀ x ∈ A (x ∈ B).

    Unique existence. logic.kurt declares the binder existsunique, written ∃! x P(x) (∃! is one symbol; in the shell \exists!). Its meaning is its definition, "existsunique-def": ∃! x P(x) iff ∃ x (P(x) ∧ ∀ y (P(y) ⇒ y = x)); with a condition, ∃! x ∈ M P(x) is ∃! x (x ∈ M ∧ P(x)) ("existsunique-cond-def"). Three rules follow from the definition and save the steps through it: "existsunique-intro" (from P(a) and ∀ y (P(y) ⇒ y = a)), "existsunique-exists" (∃! gives ∃), and "existsunique-unique" (from ∃! x P(x), P(a) and P(b) follows a = b). They are axioms, since a general proof would need sub in its lines; proofs/natural-deduction/ existsunique.kurt derives each of them from the definition alone, for a predicate P. To use the witness, get ∃ x P(x) and pick from it, or unfold the definition.

    4.5 flat and sym¶

    flat OP     ; e.g. flat "+"
sym OP      ; e.g. sym "+"

    Both require OP to already be infix. They are two separate laws, and each can be declared without the other: flat is associativity, sym commutativity; the normal form of a term and the search use each on its own. flat OP means a run of OP doesn't nest two arguments at a time in the parsed term — a + b + c parses to a single (+ a b c) rather than (+ (+ a b) c) (compare parse a + b + c before and after declaring flat), and so do (a + b) + c and a + (b + c): they are the same term, and the order of the arguments stays as written. sym OP means OP's arguments may be reordered when Kurt searches the theory for a match — an axiom about a + b also matches a goal written as b + a. An operator that is both flat and sym (like and/or) gets its arguments canonically sorted before matching, which means Kurt effectively does multiset matching on it: A and B and C matches a stored C and A and B directly, not just pairwise swaps.

    flat alone is the law of an associative operation that isn't commutative, the product of a group or of matrices (flat +, times and sym + in matrix.kurt and field.kurt). From P((a ∘ b) ∘ c) with only flat ∘, Kurt gets P(a ∘ (b ∘ c)) (the same term a ∘ b ∘ c), but not P(c ∘ b ∘ a) or P(b ∘ a ∘ c); with only sym ∘, it gets P(c ∘ (b ∘ a)) (each ∘ swapped), but not P(a ∘ (b ∘ c)); with both, every order and grouping. (A flat operator is a constant, see below: group.kurt's ∘, a variable for any group's operation, has its associativity in the definition of a group, associative($G, (∘)), instead.) Each of flat/sym can only be declared once per operator (redeclaring raises an error), and if the operator already has a partial prop signature (§5), that signature must be consistent with binary use (both argument positions statement places, or neither; no signature information beyond position 2).

    Declaring flat or sym is a claim (associativity, commutativity), so it must come before the operator is used in any formula, and it can't be made for an operator that comes with one of Kurt's theories or its core (e.g. sym - or sym implies is an error) — see "frozen operators" in §8.2. It also fixes the operator's meaning, so either declaration makes it a constant. A flat operator cannot share its symbol with a prefix form (flattening would erase the distinction between unary and binary trees); neither property can be attached to a binding or variable operator.

    4.6 chain¶

    chain OP1 OP2 ...     ; e.g. chain = <=  or  chain iff implies

    Chains of relations, in one place: a < b < c on one line is read as a < b and b < c (below, for every relation between terms, prop OP 0, declared in a chain or not), and the chain line, by the order of its relations, gives the transitivity facts, so a < c follows from it in one step (with numbers.kurt's chain = <= <: "chain-trans-2-2"); a chain can also go on over indented continuation lines. chain declares that the listed infix operators may be written one after another across indented continuation lines, mimicking how mathematicians chain (in)equalities: after a chain is declared, writing

    x = y
  < z

    is sugar for two separate checked lines, x = y and x < z (the second line's left-hand side is filled in from the previous line's right-hand side, and the operator used is the strongest one seen so far in the chain, by index in the declared list — this is why chain = < lets = , <-chains resolve to < once a < has appeared).

    Declaring a chain also generates real, directly usable transitivity axioms — one for every ordered pair of the chain's operators, using the same "pick the operator with the larger index" rule as the parsing sugar above. For chain = <= <, that includes the familiar $a < $b and $b < $c implies $a < $c, but also every mixed pair like $a <= $b and $b < $c implies $a < $c. They are named "chain-trans-I-J", by the positions of the two relations in the chain (counted from 0): < with < is "chain-trans-2-2", = with < is "chain-trans-0-2". So given x = y and y < z as two separately-proven facts (not written as one continuation-line chain), x < z really is now a single derivation step, citing the auto-generated fact (the line's reason lists the facts in the order the search used them, not in the order of the chain) — you don't need to hand-write these per theory (numbers.kurt used to; it no longer does). This only combines two facts in one hop, the same as every other inference rule — three or more links in a chain of relations still need an explicit intermediate step, same as any other multi-hop reasoning (§6.1's single-hop limitation still applies beyond one combination).

    Relations can also be chained on a single line: a = b <= c < d means a = b and b <= c and c < d, reusing each middle term. This applies to any infix operator with a statement as its result and no statements as arguments (prop OP 0, e.g. =, ≠, <, <=, in), whether or not it is declared in a chain — not to connectives like and, iff, implies. The operators of one chain must have the same binding power: with infix <= 50 50, < 50 50 and = at 20 20, a = b <= c < d is not a chain but a = ((c < d) and (b <= c)). Parentheses switch it off: (a = b) = c is still an equation between a = b and c. Since the auto-generated transitivity axioms take a conjunction as premise, a chain of two relations on one line like a = b <= c directly gives a <= c in one more step (proofs/arithmetic/chains.kurt); with three, a = b <= c < d, a <= c is not derivable in one step. A same-line chain can't (yet) be continued on indented lines below it.

    Continuation lines must be indented relative to the line that starts the chain; writing the continuation at the same indentation is a ParseError, not a chain. All declared chains together must form a DAG (no operator ordering may create a cycle across different chain declarations) — this is checked when the chain is declared. Every member must be a constant, non-binding infix relation with a statement as its result. chain adds those const and prop OP 0 declarations when necessary and reports them explicitly; a variable operator cannot acquire the generated fixed transitivity rules.

    A chain has at most three operators (at most 9 rules). With --strict (§1), outside the trusted theories, a chain generates nothing: each of its rules -- one for every ordered pair, ($a Ri $b) and ($b Rj $c) implies ($a Rk $c), the later relation absorbing the earlier, so chain = < is a different claim than chain < = -- must be a fact before the chain line, or follow in one step (checked as a line is: the search, then the kernel); a missing one is an error that lists the show lines to prove. The chain's notation (continuation lines, a ≺ b ≺ c) then uses the proved facts. Unproven, chain R for x R y meaning y = x + 1 would give 3 = 2.

    4.7 alias¶

    alias NEW OLD     ; e.g. alias "⇒" implies

    alias gives an existing symbol an additional name, resolved in the scanner (i.e. before parsing, with no inference step) — implies and ⇒ are completely interchangeable everywhere, including inside axioms already stored in the theory. This is different from def (§6.2), which introduces a genuinely new constant that needs an inference step to unfold (equal-elim for def c = ...; a def P iff ... is used directly as an implication in both directions).

    A declaration written with an alias is about its symbol: after alias ⊆ subset, tex ⊆ \subseteq or chain ⊆ declare tex/chain for subset (a declaration of the alias itself would never apply, since the scanner reads every ⊆ as subset).

    The words of Kurt's theories. In the theories that come with Kurt (src/kurt/theories/), the standard name of every symbol is ASCII, a word, and the Unicode symbol is its alias: union and ∪, as implies and ⇒, forall and ∀, <= and ≤, Nat and ℕ (todo 61). A file may write either: A ∪ B and A union B are the same term, and a line is printed as it is written, with the symbols of the line (x ∈ (A ∪ B) or x in (A union B); the brackets and the order of the arguments of a sym operator are Kurt's, and that order follows the standard names). A line that Kurt derives keeps the symbols of the facts it comes from (a theory's rules are written with ∪); the listings and messages use the standard name: list, syntax, theory's declarations, an error message (`union`), a sort signature (set union 0 1 2). kurt --latex writes a word as its symbol (union is \cup, like ∪), and kurt --lean names a symbol without a lean declaration by its word (subset, divides, times_d2). Other files are free to declare Unicode symbols as they like; but the words are symbols of the theories now, so a file that loads set.kurt can't declare a union of its own (a symbol is declared by one file only, §8.2).

    theory word symbol theory word symbol
    set.kurt in ∈ (and :) equality.kurt neq ≠
    set.kurt subset ⊂ natural.kurt divides ∣
    set.kurt superset ⊃ field.kurt, matrix.kurt times ·
    set.kurt notin ∉ group.kurt compose ∘
    set.kurt union ∪ lambda.kurt lambda λ
    set.kurt intersect ∩ lambda.kurt reduces ↦
    set.kurt emptyset ∅ (and {}) lambda.kurt steps ⇝
    set.kurt cross × lambda.kurt, modal.kurt proves ⊢
    set.kurt to → modal.kurt imp, equiv →, ⇔
    propositional.kurt true, false ⊤, ⊥ modal.kurt wedge, vee, neg ∧, ∨, ¬
    propositional.kurt implies, invimplies, iff ⇒, ⇐, ⇔ (and ≡) modal.kurt bot ⊥
    propositional.kurt and, or, not ∧, ∨, ¬ modal.kurt box, diamond □, ◇
    logic.kurt forall, exists, existsunique ∀, ∃, ∃! numbers.kurt <=, >= ≤, ≥
    natural.kurt Nat, Real ℕ, ℝ integer.kurt, rational.kurt, complex.kurt Int, Rat, Complex ℤ, ℚ, ℂ
    finite.kurt setminus ∖

    modal.kurt's connectives are those of its formulas (terms), not the core's implies, and, ...: hence imp, wedge, vee, neg, bot (conj would be complex.kurt's conjugate); ∅ is emptyset, since empty is the empty context of lambda.kurt and modal.kurt. A Greek letter that is a name stays one (group.kurt's inverse ι, an operator variable); λ, a binder, has a word.

    4.8 Inspecting the grammar¶

    syntax (with no argument) prints every declared piece of syntax at every open level; syntax SYMBOL prints just what's known about one symbol. For the facts that mention a symbol too, not just its declarations, see info (§4.9). parse EXPR parses EXPR without checking it and prints both its s-expression form -- in the normal form Kurt stores and matches (flat operators flattened, the arguments of sym ones sorted: parse c + 1 + c gives (+ 1 c c); the exception is = and iff, which are sym for the search but keep their written order: parse b = a gives (= b a)) -- and the same per-symbol syntax info as syntax. tokenize EXPR shows the raw token stream before parsing. Each of infix/prefix/postfix/brackets/arity/bindop/flat/sym/ chain/sort/prop/var/const/alias, called with no arguments, also prints its own currently-declared table.

    4.9 Inspecting loaded theories¶

    list shows which theory files are loaded. list files is the explicit spelling of the same command. Give it a loaded theory's stem or filename to see all declarations and formulas retained from that source:

    list
list files
list natural
list natural.kurt

    A category before the optional source narrows the result:

    list const                 ; every known constant
list const natural         ; constants originating in natural.kurt
list infix natural.kurt    ; infix declarations originating there
list theory natural        ; all retained formulas originating there
list use natural           ; retained axioms originating there
list def natural           ; retained definitions originating there
list syntax natural        ; every retained declaration originating there

    The declaration categories are prefix, infix, postfix, brackets, arity, bindop, flat, sym, sort, prop, chain, var, const, and alias. A declared sort name is also a category, so list term lambda shows the retained term signatures. After list, symbols and declarations are synonyms for syntax (list symbols natural). Locations in a source-filtered result refer to the original file and line.

    A source without .kurt matches the stem of a loaded file; a name ending in .kurt matches its basename; and a path selects that file. If two loaded files have the same stem or basename, Kurt asks for a path. Category names are reserved after list, so a theory called const.kurt is selected with list const.kurt.

    Loading retains a theory's exported declarations and labelled, non-local facts. Therefore list natural describes the part of natural.kurt present in the current knowledge base, rather than reproducing the source file. It cannot show local declarations, unlabelled facts, comments, or intermediate proof lines that were discarded during loading.

    list's SOURCE is always a file. To ask about one symbol instead -- its declarations (syntax SYMBOL), its def if it has one, and every retained fact that mentions it, wherever it came from -- use info SYMBOL:

    load numbers
calc on
def four = 2 + 2
four = 4
info four
; const four                                ; ...
; def four = (2 + 2)                        ; ...
; four = 4                                  ; ...

    info never resolves its argument as a file (unlike list), so a symbol and a loaded file happening to share a name never conflict: info four always means the symbol, even with a loaded four.kurt in scope -- list four still means that file.
