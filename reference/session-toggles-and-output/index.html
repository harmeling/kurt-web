    10. Session toggles and output¶

    format sexpr | normal | source     ; stored tree, readable normal form, or source spelling
hint on | off                  ; in the shell: before each prompt, what could come next
calc on | off       ; a step may follow by computing with numbers (the symbols bound with `builtin`)

    Each, called with no argument, reports its current setting instead of changing it (format also names the other options).

    format normal is the default readable form and reflects Kurt's stored normal form; format sexpr exposes the exact expression tree. format source replays the input spelling saved on a stored formula (aliases, parentheses and operand order included); an expression that was generated internally and has no independent source spelling uses normal formatting. Editors should use structured API/LSP data when they need positions rather than parsing any display.

    What calc computes is said by the theories: they bind their symbols to Kurt's built-in calculator, whose operations are add, subtract, negate, multiply, divide, power and the comparisons eq, ne, lt, le, gt, ge. number.kurt does

    builtin + add, - subtract, - negate, * multiply, / divide, ^ power
builtin = eq, < lt, <= le

    (>, >= and ≠ are read as <, <= and ¬(… = …), inline §6.2; the negation of a computed comparison holds by calc, ¬(2 = 3))

    and a symbol that isn't bound is never computed. Sets of numbers, too: the calculator knows naturals, integers and rationals, natural.kurt does builtin Nat naturals (number.kurt likewise for Int and Rat), and set.kurt builtin in element; then calc on proves 3 ∈ Nat and -3 ∈ Int, but not -3 ∈ Nat. complex.kurt binds i to imaginary: an expression of numbers, i and the operations is computed exactly with rational real and imaginary parts, calc on proves (1 + 2 * i) * (3 - i) = 5 + 5 * i, i * i = -1, (1 + i) ^ 2 = 2 * i (a power with a natural-number exponent up to 64) and i ≠ 0.

    builtin gives a symbol a meaning that Kurt itself implements: a calculator operation, as above, or a role of the engine. The engine gives no symbol a meaning by its name alone -- only the roles that the theories assign:

    role in what the engine does with it
    equivalence propositional.kurt: builtin iff equivalence a fact A iff B is used as A implies B and as B implies A; def may define with it
    disjunction propositional.kurt: builtin or disjunction case blocks for the alternatives of a fact A or B or ... close by "case-elim" (with propositional's "or-elim")
    negation, falsum propositional.kurt: builtin not negation, false falsum an assume A block whose last line is false also gives not A ("not-intro")
    equality equality.kurt: builtin = equality def may define with it
    universal, existential logic.kurt: builtin forall universal, exists existential the outer ∀s of a fact are stripped (its variables stand for anything), let closes with the universal ("forall-intro"), pick opens from the existential ("exists-elim"); they need a binder with two arguments
    setbrackets, setbuilder, emptyset set.kurt: builtin { } setbrackets, \| setbuilder, builtin emptyset emptyset (∅) sets by their elements and by a property: see below

    A role needs the matching prop signature (prop iff 0 1 2), a role has one symbol, and only a trusted theory -- one that comes with Kurt, or one from a -p directory -- can assign a role, since it changes what the engine derives (a calculator operation, like an axiom, also in other files, but not with --strict). So a file's own iff or or, without propositional.kurt, is just a relation.

    Sets (set.kurt, since 0.9): with the roles of sets, braces make three kinds of terms -- {a, b, c} by its elements (({} a b c)), {x ∈ A | P} by a property (the set-builder, the | term itself; | outside braces is an error), and {}, which is ∅. So a rule about {$y}, like set.kurt's "singleton" ($x ∈ {$y} ≡ $x = $y), never reads a set-builder or a list as its one element (before, it proved false, proofs/soundness/sets-by-their-elements.kurt), and {(a, b)} is the set with one element, the pair. For each set by its elements in a line, Kurt adds the rules for it to the file (from the source <set enumeration>, checked by the kernel like any rule): each element is one, c ∈ {a, b, c, d} in one step ("element-3-of-4"), and membership is the disjunction, $x ∈ {a, b, c} ≡ $x = a ∨ $x = b ∨ $x = c ("enumeration"), which case splits -- for a set of constants of the file this rule is of the set itself, otherwise of its length ("enumeration-n"). The order of the elements counts for the terms, {a, b} = {b, a} follows from "extensionality". About 15 elements take a second or two; a disjunction of twenty or more is slow to find (dev/todo.md, speed).

    With interval.kurt, ... lists numbers: {a, ..., c} in steps of one ("range"), {a, b, ..., c} and {a, b, ...} in steps of b - a, for a < b ("progression", "progression-intro", "progression-infinite", ...) -- each membership is an ∃ k ∈ Nat (proofs/natural-numbers/progressions.kurt). One or two elements fix the step; more, as in {2, 3, 5, 7, 11, ...}, would only suggest a pattern, which Kurt can't know, so it refuses them: write a set-builder, {p ∈ Nat | prime p}.

    The set-builder is one construct with three parts: the variable x, the set A it ranges over, and the statement F -- "the set of the x in A with F". Kurt writes it with two pieces of syntax, the braces and the binder | (it has no operators of three pieces), and reads it as one term: the braces are dropped (set_terms), and the | node remains with two arguments, the binding condition x ∈ A (the variable and its set together, as in ∀ x ∈ A F) and the body F. So the variable is bound like by any binder (§4.4), the body is a statement (§5.1), and x ranges over the elements of A. Without a set, {x | F} is refused: unrestricted comprehension would allow Russell's paradox (set.kurt's "separation" only carves a part out of a given set).

    Vectors and matrices (matrix.kurt, load matrix): a bracket pair bound to matrixbrackets (builtin [ ] matrixbrackets, both brackets of a pair declared with brackets [ ]; a bracket pair takes no other role) makes literals of numbers -- [1, 2, 3] a row, [[1, 2, 3], [4, 5, 6]] a 2x3 matrix row by row, [[1], [3], [5]] a column (a row [1, 2, 3] and the one-row matrix [[1, 2, 3]] are the same value) -- and the operations add, subtract, negate, multiply (a number times a matrix, or a matrix times a matrix), transpose, determinant and the comparisons eq, ne compute them exactly (/ divides numbers only). Shapes that don't fit give no value. Written over several lines, each line inside the brackets is a row, as on paper:

    A = [1, 2, 3
     4, 5, 6]          ; is [[1, 2, 3], [4, 5, 6]]

    In normal screen output, a matrix with two or more rows is printed on aligned lines, while row vectors stay compact:

    [[  1, 20],
 [300,  4]]

    This is display only. Saved .kurt source keeps the accepted input lines, and format sexpr keeps its one-line structural representation. format source shows the spelling originally entered for a stored formula.

    (a line break inside a bracket pair bound to matrixbrackets -- builtin [ ] matrixbrackets -- without another one in it ends a row; elsewhere it is a space, also inside a [ ] that isn't bound: the theory makes the brackets special, not Kurt). matrix.kurt has its own +, -, ·, so it isn't loaded together with number.kurt (§8.2); it computes with literals and has no laws for matrices written with variables (for those: proofs/mafi1/matrices.kurt, over a field). As everywhere with calc on, a name defined as a matrix (def A = ...) isn't computed in the same line: replace it first, one step per line.

    A binding is like an axiom (1 + 1 = 2, 2 + 1 = 3, ...), so --strict rejects it outside the trusted theories, and the symbols of a trusted theory can't be bound anew. Numbers bound to calculator operations are constants: the binding supplies fixed semantics and reports const SYMBOL ; added constant if that role was not already known. A variable or binding operator cannot also be calculator-bound. Numbers are exact: integers, decimals (0.1 is exactly one tenth, so 0.1 + 0.2 = 0.3 holds), and fractions, which stay fractions (1 / 3 + 1 / 3 is 2 / 3). What has no exact value isn't computed: 1 / 0, 0 ^ -1, 2 ^ 0.5, and 0 ^ 0 (which number.kurt leaves open). Neither is a result with more than 1000 digits, and a longer number literal is a ScanError. 0 + x and 1 * x are x, 0 * x is 0. In number.kurt, ^ is right-associative and binds more tightly than the prefix -: - 2 ^ 2 is - 4, and 2 ^ 3 ^ 2 is 2 ^ 9. A decimal with an integer value is that integer: 1.0 is 1.

    With calc on, a line may follow by computing -- it is not changed: it is stored as written. It follows if its computed form follows (e.g. 1 + 1 = 2 is computed to 2 = 2, by calc), searched with the computed forms of the facts written with calc on -- or, if not, as written (so (1 + n) * (1 + n) = 1 * (1 + n) + n * (1 + n) is an instance of "distrib-add", and from 7 = 1 + 6 follows ∃ k (7 = 1 + k)). No symbolic simplification. A comparison of numbers (e.g. 3 <= 4, 2 + 2 < 5) is proven directly "by calc", and a claim follows "by calc" from a fact that computes to the same thing (e.g. x = -25 from x = (-5) * 5). (Before 0.9 each line was computed when it was read.) Results of substitutions (sub, as in induction or equal-elim) are computed too: substituting k + 1 into $x + 1 gives k + 2, not k + 1 + 1. While matching a rule, a part of it is computed as soon as its variables have values: with $n := 3, the ($n - 1)! of "factorial-step" matches 2!, and after def f($x) = $x * $x, f(3) = 9 follows in one step. But calc doesn't solve: the $b / $c of "gt-div-pos" doesn't match 0 while $b is still unknown -- state such steps as their own lines, or use a rule that fits (like "div-pos"). Nor does it combine a rewrite with a calculation: x = 6 doesn't follow in one step from x = 2 * y and y = 3 -- write x = 2 * 3 in between, then x = 6 follows by calc. Not implemented on purpose: solving for an unknown while matching, or several steps at once, doesn't fit the idea that each line is one step a reader can check (§6.1); the line in between is the step. calc on holds for its block and the blocks in it, and ends with it (and with its file): after the qed of a proof that switched it on, it is off again (before 0.9 it stayed on). With hint on, the shell prints before each prompt what could come next (; hint: next, e.g. proof): proof after a show, in a proof its goal and then qed, in a chain its relation, in a case block the other alternatives -- Tab on an empty line writes it.

    breakpoint, a line in a proof file: at a terminal (or with kurt -i FILE), checking stops there and the shell continues with that state -- the open blocks, the facts, what is still to prove; try steps there, then write the one that works into the file (Ctrl-D ends the shell). Without a terminal (the playground, Kurt from Python), it shows that state and checking goes on. In a file that another one loads, it is skipped. After an error, kurt -i FILE likewise continues in the shell at the failing line, with the state there (keywords/42-breakpoint.kurt).

    Tab in the shell (at a terminal) completes: on an empty line the next step (as hint); after = with calc on the value (17*42= and Tab gives 17*42=714); a LaTeX shortcut its symbol (\forall and Tab gives ∀); after load a theory or a .kurt file here; otherwise keywords, symbols and labels ("and- gives "and-elim"). With several possibilities, Tab writes what they have in common, and a second Tab lists them. It only writes text; every line is checked as usual.

    help prints Kurt's own one-line description of every keyword, help use the one of use.
