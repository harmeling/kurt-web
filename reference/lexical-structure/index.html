    2. Lexical structure¶

    Kurt reads a proof one statement at a time; a statement occupies one or more physical lines (see §2.1 on indentation/continuation).

    • Comments and labels are two different things, with two syntaxes. A comment starts with ; and runs to the end of the line; Kurt ignores it completely. A ; inside a string is part of the string ("x;y" is a label), and a lean "label" TACTIC line has no comment (it takes the rest of its line raw, ; too). A line with nothing but a comment is skipped like a blank line, whatever its indentation (§2.1). A label is a string written after a fact: use A implies B "mp", show A implies C "ac", Q "derived-q" (a bare claim), def ... "name". It names the fact in Kurt's output (; by mp(3) instead of ; by 2(3)), in error messages and in --foundation, and a label that isn't marked local exports the fact to a file that loads this one (§6.1, §6.2, §8.2). A comment never labels: use A implies B ; mp is an unlabelled fact.
    • Symbols (identifiers) are [A-Za-z][A-Za-z0-9]*, optionally followed by primes (a', f'') and preceded by $, % or $$ (variables, see §3.2). A Greek letter followed by digits or primes is one symbol too (λ1, ε'), also as a variable ($Γ, %φ, $Γ2). Plain multi-character identifiers remain ASCII; Greek letters next to each other (αβ) are individual symbols.
    • Numbers are INT ([0-9]+) or FLOAT ([0-9]+\.[0-9]+) literals.
    • Strings are "..." (no escaping of embedded quotes); used for labels (use ... "my-label") and for some keyword arguments that take an operator symbol as text (infix "+" 20 20).
    • Operator characters. Besides letters/digits, (, ), {, }, [, ], and , are always their own single-character symbols — they never glue to each other or to anything else, precisely so a custom brackets pair keeps working next to unrelated punctuation with no space (e.g. a trailing ...} is two tokens, ... then }, not one token that swallows the closing brace). A run of characters from .:=+-*/#&^'∈!<>|_~ (note: no brackets in this class) glues together into one symbol instead (so declaring != gives you a single two-character operator, but writing !! without spaces is one symbol !!, not two ! tokens). A fixed set of additional Unicode symbols is recognised one character at a time — exactly the symbols that appear as values in Kurt's LaTeX-input table (§2.2): the common logic/set-theory symbols (∀ ∃ ∧ ∨ ⇒ ⇐ ⇔ ¬ ⊤ ⊥ ∈ ∉ ∋ ⊂ ⊆ ⊃ ⊇ ∩ ∪ ∖ ∁ ∅ ≡ ∘ ↦ ⇝ → ⊢ ∞ ≤ ≥ ≠ × · ∣ ⟨ ⟩ ⟂ ∼ ≈ ≺ ≼), modal-logic symbols (□ ◇), and the Greek alphabet; ∃! and ⁻¹ are one symbol each. Any other non-ASCII character is a lexing error — you cannot declare an operator using an arbitrary Unicode symbol that isn't already on this list.
    • load (and list, tex, lean) are special in the lexer. A line starting with load (case insensitive) is scanned specially: everything after it up to a ; or end of line is taken as a comma-separated list of filenames (quoted or bare), not parsed as an expression. This is why load propositional, equality and load "my-theory.kurt" both work, without propositional/equality/"my-theory.kurt" needing to be otherwise-valid symbols. tex SYMBOL ... and lean SYMBOL ... take the rest of the line raw, as LaTeX or Lean text (§1, documents and Lean), up to a comment; lean "label" ... (a line of a proof in Lean) takes all of it, ; too -- such a line has no comment.

    2.1 Statements, indentation, and line continuation¶

    A statement can span more than one physical line: if a line ends mid-expression, Kurt automatically treats the next line as its continuation — no explicit continuation marker is needed.

    In a file, indentation is significant, and the same in the shell (§9). The rule:

    • The indentation of a line is the number of its leading spaces. A tab moves to the next multiple of four (a tab stop every four columns, Python's expandtabs(4)): ⇥ and ␣␣⇥ are both 4, ␣␣␣␣⇥ and ⇥⇥ both
    • There is no option or environment variable for this, and none for the width of a block; -r N (§1) sets only the column of the reasons in Kurt's output.
    • A block opens with proof, assume, case, let, pick, sandbox or expect (§7, §9): the next line must be indented more than the opening line -- by any number of spaces (2, 4, 7, ...; Kurt's own output and the shell use 4) -- and that indentation is the block's: every further line of the block has exactly it. A line indented less closes blocks until its indentation is that of an enclosing block, and it must hit one exactly ("does not match any previous block"). A line indented more without a block opening before it is an error ("unexpected increased indentation"), except for the continuation lines of a chain (§4.6).
    • A blank line, or a line with nothing but a comment, is always safe anywhere, at any indentation, including deep inside a nested block: it's skipped outright rather than measured, so it never closes a block on its own. A comment at the end of a line (assume A ; the premise, qed ; done) changes nothing either.
    • A statement continued over several lines (a line that ends inside brackets or after an operator, use (A implies then B)) is read as one: the indentation of its continuation lines doesn't matter, and a blank or comment line inside it is skipped.

    2.2 LaTeX-style input shortcuts (interactive shell only)¶

    Typing Unicode symbols is inconvenient on most keyboards, so in the interactive shell, before a line is scanned, Kurt rewrites LaTeX-style commands to their Unicode equivalent: \forall → ∀, \exists → ∃, \implies → ⇒, \invimplies → ⇐, \and/\or/\not (or \neg)/\iff/\equiv/ \top/\bottom → ∧/∨/¬/⇔/≡/⊤/⊥, \in/\notin/\subset/\subseteq/ \supset/\supseteq/\cup/\cap/\emptyset/\to/\mapsto/\leadsto/\circ, \times/\cdot/\mid/\langle/\rangle/\infty, \leq/\geq/\neq, \box/\b/\diamond/\d (modal logic), \vdash → ⊢, and the full Greek alphabet (\alpha, \Gamma, ...). The standard LaTeX names work too: \le/\ge/\ne, \lnot, \land/\wedge, \lor/\vee, \Rightarrow, \Leftrightarrow, \bot. This replacement only happens for lines typed at the interactive prompt — it is not applied when reading a .kurt file. A saved proof file must already contain the real Unicode characters, or the ASCII words: every symbol of Kurt's theories has one (union for ∪, §4.7), and a file's own symbol gets one with alias.
