    3. Terms, symbols, and their roles¶

    Every parsed term (Expr internally) is either a single symbol/number/ string (a leaf) or an operator applied to one or more sub-terms. There is no separate "statement" syntax — a term is a formula once it's been checked to be a statement (§5).

    3.1 Function application is just an infix operator¶

    Space is a built-in infix operator (declared in the hard-coded minimal.kurt, see §8.1), so f x means "f applied to x". A symbol without an arity is curried: f x y is f x, applied to y, and (f x) y is the same term -- both are stored as one call, (f x y) (so f x is no subterm of it that a rule could rewrite). With a declared arity (§4.3), f takes exactly that many arguments, and further ones apply to the result: with arity f 2, f x y z is (f x y) z, and (f x) y is an error, f x lacks an argument -- a forgotten argument or a misplaced bracket is caught. f(x, y) is something else: f applied to one argument, the pair (x, y) (§4.3). Where a function is applied in steps as a term of its own, as in the lambda calculus, a theory writes application as an operator (lambda.kurt). This is also why you can write not A even though not is declared as a prefix operator elsewhere — a bare symbol symbol juxtaposition is space-application regardless.

    Function application binds more tightly than every other operator, as in mathematics: f x + y and f(x) + y are (f x) + y, and s n in Nat is (s n) in Nat. Parentheses only group, so f(x) is just f x -- with one difference: a bracket written directly after a symbol, without a space, makes one term that binds more tightly still. So inv det(A) is inv (det A) (while inv det (A) is inv det A, inv with the two arguments det and A), and in the condition of a binder, ∀ $x ∈ Perp(M) Q($x) reads Perp(M) as one term.

    3.2 Constants vs. variables¶

    Every symbol in a formula is exactly one of (before its first use, a symbol with only a shape or type declaration, infix, arity, prop, is neither yet, §3.4):

    • a constant — one fixed, specific object, declared with const x, or implicitly whenever it's introduced by let/pick/def/brackets, or the first time a symbol that isn't a variable (no sigil, no var) is used in a formula (e.g. after use P c, both P and c are constants; prop only records the statement places of a symbol, see §5, not whether it is a constant). Such a first use is shown as an ordinary declaration in the output (const P ; added constant), including when the symbol already had a syntax or type declaration such as infix P ... or prop P. A wholly undeclared symbol is often a typo; with --strict (§1), it is an error instead. Or
    • a variable — may stand for arbitrary objects, declared with var x.

    Once a symbol's role is fixed on a given level (see §9 on blocks/levels), it cannot be changed in either direction on that level: declaring const x then var x fails, and so does the reverse. A symbol that is a constant inside a block can still be an ordinary (as-yet-undecided) symbol outside it, once the block closes and its constants go out of scope.

    A var needs no let in a proof. A show about declared variables is a claim for all of them, and its proof works with them as they are: no let x, y first (that is for a const-like fresh object, §9.2). After var x, y, show x > y implies not x = y is proved by assume x > y, assume x = y, ... directly (regression test: proofs/debug/var-needs-no-let.kurt).

    A sort with the names. var real x, y, z declares the variables x, y, z and gives them the sort real: it is var x, y, z followed by real x, y, z (§5.2); const real c, d is const c, d and real c, d the same way. Only the plain form: a sort in front of the list, no places (real x 0 is the sort line of §5.2 itself).

    How Kurt handles variables (the design, kept as it is on 2026-10-15):

    • A variable stands for anything: a use, def or todo with a variable in it is a schema, which the search instantiates by matching -- use $a = $a gives c = c for every term c. A variable is written with a sigil, $x for a term and %A for a formula -- or as a plain name declared with var x, which is the same thing in nicer clothes: the theories write var n, m and then use n + 0 = n, as a textbook would. Kurt shows the schema it reads (; schema: ∃ z (R z $x)), and warns when a use only relates declared variables (use a <= b with var a, b says every number is below every number).
    • A constant stands for one object. const c declares it; let x, pick c and def introduce one; so does the first use of an undeclared name.
    • Inside a block, a variable can be held fixed: let x (a new name, or a declared var x; let $x is a type error, a $ name is always a variable) makes it an arbitrary but fixed object for the block, and closing the block gives the ∀ (§9.2); an assumption's variables are fixed inside it the same way (assume P $x: one $x throughout the block).
    • load exports no variable: a loaded file's var n stays its own, and its schemas arrive with internal variables ($$07), so the loader's n is free for anything. A declared var of the loader can't be a constant of a loaded file, or the other way round (§7 of doc/kurt-soundness.md).
    • Variables are never a value of each other's binders: a $T under a binder over $i stands for a term that doesn't depend on $i, unless the rule only ever uses it under that binder or with a substitution for $i (sum $i ($a, $b) $T; doc/kurt-soundness.md §8.10).

    The alternative -- variables only with a sigil, no var -- was weighed and rejected: it would make the theories and lecture notes uglier for a tidiness that the warning and the ; schema: output already give.

    The sigils, in one place. A variable written with a sigil is a variable by its name alone, everywhere, without a declaration:

    sigil the variable example
    $x a term variable: stands for any term (an object) of its sort use $a = $a
    %A a statement variable: stands for any statement use %A and %B implies %A
    $$x a polymorphic (polysorted) term variable: the bound variable of a rule for a binder over any sort (§5.2) logic.kurt's ∀ $$x %A ⇒ sub $$x $a %A

    There are two kinds, $ and %, because a statement is no object (§5.1; decision 17 of dev/todo-sorts.md): a term and a statement are never a value of the same variable, so the sigil says which a variable stands for. $$ is a $ that isn't tied to one sort.

    A sigil and the sorts (§5.2). A term variable has a sort like every symbol: $x ranges over the objects of its sort and of the smaller sorts, and the sigil doesn't say which. The sort comes from a declaration (real $x or var real x, set $A), from a place of an operator where it is used ($x + 1 is a number, $x ∈ $A takes an element of any sort on the left, a set on the right) or from default real of the file; without any of them it is any, the sort of all objects, so $x is any object. A statement variable %A has no sort: it is no object. $$x is the one exception, a variable that has no sort of its own: a rule with a binder ∀ $$x ... is polymorphic (polysorted): each use of the rule takes the sort of the binder it is matched with (∀ n (...) over the numbers, ∀ A (...) over the sets), once per use (the rule can't mix two sorts). Because of that, $$x may occur only in its binder, in subs and as a side of =. There is no other sigil: @x is a scanning error. A plain name declared with var is a variable too (a term variable, or a statement variable with prop, §5.1).

    Symbols starting with $ or % are always variables: const $x is an error ("symbol $x starts with $, so it is always a variable and can not be declared a constant"); var $x is accepted and changes nothing, and a $x never becomes a constant by its first use. They exist specifically to write axiom schemas in use lines, where $x stands for an arbitrary term (e.g. use $a = $a) and %A stands for an arbitrary statement (e.g. use %A and %B implies %A); mixing them up is a type error ($A implies $A), and no step gives a $-variable a formula or a %-variable a term as its value (the search refuses it, the kernel checks it again). let fixes a term only (let %A is a type error since 2026-10-20): a statement variable needs no let, in a proof it stays the same statement, and an assume holds it fixed in its block (§5.1). You'll see $-variables and %-variables throughout every .kurt theory file under src/kurt/theories/.

    3.3 What "new" means¶

    Because there's no separate declaration step for most symbols, const/ var/prop mostly exist to be explicit, to catch typos (redeclaring the same symbol raises an error), and to control what "new" means for keywords that require a genuinely fresh symbol (def, let, pick, brackets).

    3.4 Who declares what: the rules in one place¶

    Most symbols are declared by using them. What each kind of line does to a symbol:

    line the symbol is then
    $x, %A, $$x anywhere a variable, by its name alone: $x for a term, %A for a formula, $$x for a term of any sort (needs no declaration, never a constant)
    var x a variable (also an operator: infix ∘ 50 50 and then var ∘)
    const x a constant
    brackets ⟨ ⟩ both brackets constants
    def g = ... g a new constant (a new symbol on the right side is introduced as on any line)
    let x, pick x a constant inside the block (one arbitrary object); after the block, x is free again. x is a new name or a declared var x; an existing constant, a name fixed by an enclosing assume, and a $/% name are errors
    assume P $x $x fixed inside the block (not a variable there)
    arity, infix, prefix, postfix, prop, and a declared sort such as nat declared, but neither constant nor variable: these give shape or type information only
    sort nat nat a reserved sort name and declaration keyword, never a term symbol
    binder, flat, sym a constant: each gives the named operator fixed semantic behavior
    chain OP... every named relation a constant with a statement as its result (prop OP 0), because chain adds fixed transitivity rules
    builtin x operation x a constant with the fixed calculator meaning (a bracket binding applies to the bracket expression); with a role of the engine (builtin iff equivalence), x keeps what it is
    alias new old new another spelling of old, including old's constant/variable role and properties
    the first use in a formula of a symbol that isn't a variable a constant, reported as const SYMBOL ; added constant

    Further rules:

    • The prop signature comes from the first use (§5), unless declared with prop: a symbol at a statement place is a statement (use P a makes P one, a not), an operator whose arguments are statements gets these places. Each inferred signature is reported as a valid declaration, for example prop P 0 ; added statement places.
    • Declare before the first use. After it, const, var, prop, a user sort, arity, infix, prefix, postfix for that symbol are errors ("already used in a formula"): the formula was read with what was known then.
    • Syntax and meaning are separate. Fixity, arity, prop, and optional sorts say how a symbol is parsed and typed; they deliberately do not decide whether it is a constant or a variable. binder, flat, sym, chain and calculator bindings do decide: their behavior belongs to one fixed operator, so Kurt makes it a constant and prints the implied declaration. A variable operator may still have fixity, arity and a prop signature, as group.kurt's schematic ∘ does.
    • The variable of a binder. Without a condition, ∀ x (...) binds x (a new name or a variable; it doesn't become a constant). The bound variable is written as a plain name, ∀ x (x = x), ∃ x > 0 P(x): it needs no declaration and no sigil, and a $ on it (∀ $x ($x = $x)) is accepted but not needed. The sigils $ and % are for the free variables of a rule (use $a + 0 = $a, use %A ⇒ %A), where they say "for any term" or "for any statement"; a free plain name is a constant. With a condition, it binds the first symbol of the condition, as written, that is new or a variable and not bound by an enclosing binder: x in ∀ x > 0 (...), x in ∀ c < x (...) with a constant c, $x in ∀ (P $x) (...) with a predicate P, x in ∀ (0 < e) (∀ (e < x) ...). Kurt decides it when it reads the line and stores it with the condition (§4.4), so the binder binds the same variable for the rest of the file -- also when a block closes and its constants are free again. A condition without such a symbol is an error ("has no variable to bind").
    • load brings the symbols that the exported facts need and the ones the file declares at its top level without local (§8.2), with their declarations.
    • --strict (§1) keeps all these rules but one: the first use of a symbol that wasn't declared at all (neither by a line of the table nor by an earlier use) is an error, not a new constant. A declaration like prop Q or infix ∘ 50 50 counts. (It also refuses use, todo and chain outside the trusted theories.)

    Variables, constants and binders in one place (the four rules, checked 2026-10-30):

    1. A variable is ad hoc or declared. $x (a term), %A (a statement) and $$x are variables by their name and need no declaration; a plain name is a variable after var x. A plain name that is neither declared nor a variable is a constant from its first use on a formula.
    2. let and pick introduce a constant, and take only a new symbol. The name is new (never used as a constant) or a declared var x, which becomes a constant of the block. They refuse an existing constant ("already a constant and can not be declared freshly again"), a name that an enclosing assume fixed, and an ad hoc variable: let $x, let %A and pick $x with ... are type errors, because a $ or % name is always a variable (as const $x is an error). A claim with free $-variables needs no let: they are one arbitrary object in its proof, and so is a var. pick works the same as let, and pick x, y, z with F picks several witnesses (§9.3).
    3. A binder binds a variable or a new symbol, never a constant. ∀ x, sum i, lim v bind a plain name that is new (it needs no declaration and stays undeclared), a declared var, or a $x; a constant is refused ("first arg of binding operator must not be constant ... give the bound variable another name"). Names fixed by an enclosing block (let, pick, assume) count as constants there.
    4. sub $x $a A is a binder over $x with two extra rules: its first argument must be a variable ($x or a declared var x), not a new symbol; it is written only in use and def (in a claim, write the result of the substitution); and it is never nested.
