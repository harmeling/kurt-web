    11. Known gaps (so you don't mistake them for bugs in your proof)¶

    • Derivation is single-hop (§6.1) — chain several A implies B facts manually, one derived line at a time. The one partial exception: two facts using operators from the same declared chain (§4.6) combine automatically in one step ($a < $b + $b < $c → $a < $c, etc., including implies/iff chains) — but that's still exactly one combination, not arbitrary-length automatic chaining.
    • and-elim needs load propositional (or a manual axiom instance) — it is not hard-coded the way and-intro is (§8.1).
    • A custom brackets pair does not disappear the way ( ) does — it stays a real operator, printed as e.g. []/{} in s-expression form (§4.2).

    11.1 Not implemented, maybe never¶

    Features that were considered and left out, at least until after 1.0 -- some on purpose:

    • calc that solves (§10): matching $b / 3 against 0 while $b is still unknown, or a rewrite and a calculation in one step (x = 6 from x = 2 * y and y = 3). On purpose: each line is one step a reader can check; write the step in between (x = 2 * 3, then x = 6).
    • def by pattern matching on constructors: constructors Nat 0, s (Nat is built freely from 0 and s: every element is 0 or s n, s n ≠ 0, s injective), then def fact 0 = 1 and def fact (s $n) = (s $n) * fact $n -- a recursive definition that is a definition, not an axiom. It would need the patterns to be constructors only, not to overlap, and the recursion to be structural (otherwise def f (s $n) = f (s $n) + 1 gives 0 = 1), and constructors is itself a claim about Nat (to be proven, or allowed only in trusted theories). Until then, recursive definitions are use axioms with a label (like "factorial-step" in number.kurt).
    • A normalizer for ring expressions (like Lean's ring): a line "by ring" holding if both sides are equal as polynomials, e.g. the ad - bc computations of 2×2 determinants in one line. It would need a declaration of which operators form a commutative ring and a large piece of trusted code, and a reader couldn't check such a line by one rule -- the same reason as for calc that solves. Instead: each rearrangement is a line, with the laws of the theory (proofs/mafi1/ does so); missing laws, like $a - ($b - $c) = $a - $b + $c, belong into the theory.

    • calc/eval that unfolds a user's own recursive function: print the value of e.g. fact(3) by repeatedly applying a function's own axioms (fact-zero, fact-step in number.kurt) until none apply, instead of only folding the small set of built-in arithmetic operations calc on already folds. On purpose, for now: those built-ins are hand-coded, trusted, and provably terminating; a user's recursive axioms carry no termination or confluence check, so an automatic "reduce until done" loop over them is a different, riskier kind of automation -- it could loop forever on a badly-stated recursion, and printing a trusted answer instead of a checked proof would break the rule that every claim gets a reason the kernel can check (doc/kurt-soundness.md). Until constructors and structural recursion (above) make def fact a real definition, write the unfolding as an explicit one-step-at-a-time chain instead.

    • Sort parameters (deferred, 2026-10-20): a structure over a carrier of a sort of its own, e.g. the integers as a group, group(Int, (+), 0, (-)). group.kurt's rules are over all objects ($a ∈ $G), and + takes numbers, so the instance doesn't fit the sorts. The operator could bring the sort along (polymorphic elements $$a, the sort of the use fixed by +), but group.kurt is full of $a ∈ $G, which a polymorphic variable may not be in (extensionality over the numbers alone would give ∅ = {∅}), and its definitions would have to be families, one per sort: real sort parameters for defs and rules, with a soundness argument of their own. Until a course needs it: a file about the integers as a group states the group facts it needs for + itself (dev/todo.md 40).

    • Two substitutions in one formula (not wanted, 2026-10-20): sub $x $T (sub $y $N M) is refused, and so is a sub in a goal. The search finds the value and the hole of a sub from the goal (sub_solutions), for one hole; two would make the matching higher-order unification. Only "the substitutions commute" needs it, for an older proof strategy -- preservation and Church-Rosser by parallel reduction need one sub per step (doc/kurt-current-limits.md §2.3).
    • A rule with a hypothetical premise for Kurt's own binder (not wanted, 2026-10-20): the typing rule of a named λ, has (extendx Γ x A) M B ⇒ has Γ (λ x M) (fun A B), is accepted but can't be used -- x is the binder of λ x M and an ordinary argument in the premise, and when the binder matches the goal's name, the other occurrence keeps the rule's own. Making it work would let the goal's bound name leave its binder, free in the premise -- the area of capture and eigen variables where the worst soundness bugs were -- and it would need a freshness condition Kurt can't state. The de Bruijn presentation of lambda.kurt has the general rule without the problem.
    • A second quantifier symbol for let (not wanted, 2026-10-20): let closes a block with the one universal quantifier, pick opens one from the one existential. The sort of a binder distinguishes the ranges already (∀ X over sets, ∀ n over numbers; second order as let X ∈ ℘(Obj)); a second symbol would be a second spelling, and its dispatch by sort would enter the kernel's block rules. A different display is notation (tex, inline).

    11.2 Why no namespaces (yet)¶

    Two theories loading symbols with the same name can't collide the way import does in most languages: "a symbol is declared by one file only" (§8.2) -- load number, field simply can't both declare +. Where you would expect to need a namespace -- group.kurt, field.kurt, vectorspace.kurt each wanting their own +/∘ -- Kurt uses an operator variable instead: their theorems are stated over a schematic $op (var ∘, infix ∘), instantiated at a concrete operator as an argument (group(R, (+), 0, (-)), tutorial/24), not as a qualified name. "Which +" is something you pass in, not something you look up.

    The one real collision in the bundled theories is ⊢: modal.kurt's "A is a theorem" and lambda.kurt's typing judgment Γ ⊢ M : A are genuinely unrelated notations that happen to share a glyph, and only matter if one file loads both. A general lexically-scoped namespace ("open a block, use a theory's notation inside it, close it, the notation is gone") sounds like the fix, and the infrastructure for it already exists: KnowledgeBase is a stack of levels, and a declaration (infix, binder, arity, ...) is visible only from the level that made it and its descendants -- a lookup (is_infix, is_binder, ...) walks up parent, never sideways or down.

    But there's a catch that makes this harder than it looks. When a block closes and one of its formulas escapes to the surviving level (assume's "impl-intro", let's "forall-intro", ...), any notation that formula needs travels with it -- the declaration is promoted to the surviving level, the same way a load's exported facts carry the notation they need (§8.2); otherwise the surviving formula couldn't be printed or re-parsed. But that also means the declaration is no longer scoped to the block once anything escapes using it: Kurt tracks every symbol "used in a formula" (parent-chain aware, like the lookups above) and permanently refuses to redeclare it differently anywhere reachable from that point on (EvalError: symbol \...` has been already used in a formula, declaring it now would change what that formula means`) -- on purpose, since silently changing what an existing fact means would be unsound. So "open a namespace, use conflicting notation, close it, reuse the symbol differently later" does not actually work today if anything inside the block survives it: the two meanings would need to be two different symbols internally, not two lexical scopes of the same one.

    The smaller fix that's actually in scope is not a general namespace system, but a load-site rename for the rare real collision, so the common case stays exactly as readable as it is now and only the colliding pair needs one explicit line -- see dev/todo.md #21.

    Since a grammar declaration inside assume/case/let/pick/proof was never actually scoped to the block for the reason above, it is now rejected there outright (§4.1, §6.2), the same way use/load/chain/inline already were (a def is allowed in a block since 2026-10-27: its symbol is a constant of the block, gone when it closes, and no result may mention it -- so nothing of it escapes, §6.2): infix, prefix, postfix, brackets, arity, binder, flat, sym, alias and sort must be declared at the top level, or inside a sandbox/expect whose content is discarded anyway. This closes the one case that used to look like it worked (nothing escaped the block in the test files that tried it) but was never actually safe in general.
